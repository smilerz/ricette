# Authentication

Local email-and-password accounts (MVP), provided by **Laravel Fortify** (the official headless
authentication backend) with our own Svelte pages. We configure and extend Fortify rather than
writing account machinery ourselves; more features (password reset, email verification, two-factor,
single sign-on) can be switched on or added later.

## Behavior

- **Register** (`/register`): name, email, password and confirmation. The password must be at least 12
  characters. A successful registration signs the person in and goes to the home page.
- **Sign in** (`/login`): email and password. A wrong password and an unknown account get the same error.
  The session id is renewed on sign-in, and sign-out invalidates the session and rotates the CSRF token.
- **Sign out** (`POST /logout`): signed-in users only.
- **Throttling**: five failed sign-in attempts per minute for the same email and address; further attempts get
  HTTP 429. Fortify provides the limiter; the key uses the normalized email.

## Email identity

`App\Support\EmailAddress::normalize` is the single definition: lowercase and trimmed. The `User` model applies
it whenever an email is set, and registration and sign-in apply it to input, so `Ana@Example.com` and
`ana@example.com` are one account.

## Passwords

Passwords are hashed with **Argon2id** ([`config/hashing.php`](../../config/hashing.php), `HASH_DRIVER`, memory/time/threads settings) and
never stored or logged in plaintext. Hash verification is strict: a hash from a different algorithm does not
verify.

## Unique account identity

Uniqueness of the normalized email is enforced by the database's unique index on `users.email`. The validation
rule gives a friendly error in the common case; a registration that loses a race hits the index, and the insert
(run in a transaction so it rolls back cleanly on SQLite and PostgreSQL) is turned into the same error instead
of a server error. A duplicate creates nothing and never overwrites the existing account.

A duplicate registration is told the address cannot be used, and a successful registration signs the person
in. This is the maintainer's explicit product and security decision (2026-09-25), chosen for user experience:
account enumeration is not a significant threat for this application today. The MVP requirement only demanded
unique normalized emails, not a particular response. If the threat model changes, non-disclosure can change this
response without touching the database rule.

## Error messages

Registration messages are translation keys defined in [`lang/en.json`](../../lang/en.json); the Svelte pages translate them
(ADR-0024). Messages generated by the framework itself (for example the sign-in failure and throttling text)
come from Laravel's built-in English files and are shown as-is until server-side messages are brought into the
catalogs.

## Not included yet

Password reset, email verification, two-factor authentication, passkeys, remember-me, profile and password
updates, and third-party or SAML/OIDC sign-in. Fortify supports most of these; each is enabled in
[`config/fortify.php`](../../config/fortify.php) when its requirement is scheduled.
